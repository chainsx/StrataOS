# StrataOS component format v1

## SquashFS layout

```text
meta/strataos/component.conf
meta/strataos/files.sha256
meta/strataos/manifest.json
meta/strataos/packages.json
meta/strataos/hooks/
rootfs/
```

The filename is `<name>-<version>-<full-sha256>.squashfs`.
Initramfs verifies the complete 64-hex file digest against that suffix before mounting.
This detects modification but is not a publisher signature.

`rootfs/` is an OverlayFS lower directory. Control metadata remains outside the
merged root. `manifest.json` records architecture, priority, dependencies,
package provenance and a per-file manifest. Target ownership is generated by
StrataOS path/account policy and written through SquashFS pseudo definitions;
it never inherits host UIDs as a packaging contract.

## Required manifest keys

`format`, `name`, `version`, `summary`, `type`, `architectures`, `priority`,
`requires`, `after`, `services` and `storage.count` are required. Source manifests
may list every architecture that can be built. Packaging rewrites `architectures`
to the single target architecture; initramfs and `componentctl` reject a mismatch.
Unknown base keys are rejected; extension keys must use `x.<namespace>`.

Each `storage.<n>` declares `id`, `image`, `mount`, `format`,
`initial_size_mib`, `growth`, `redundancy`, `lifecycle`, `schema` and optional
`legacy_component`, plus validated bind mappings. `legacy_component` permits a
renamed or split component to adopt the same volume ID from its former owner;
the manager also applies the former owner's storage overrides and performs
rollback-safe member moves for mirrored volumes. Format v1 supports ext4 logical volumes and
`inherit`, `none`, `mirror`, and `integrity-mirror` redundancy values.

## Data ownership

A component declares whether a volume exists. The release image contains no
pre-created component data image. On first activation the trusted initramfs
manager creates or assembles the declared volume, checks/grows ext4 and mounts
it at the declared path. A volume identifier is local to its owning component;
the stable identity is component name plus volume id.

Hooks are included in the component digest, but format v1 does not automatically
execute migration hooks. Persistent schema changes require an administratively
validated migration before activation.

## Activation

The active slot contains an ordered list of component paths. Initramfs verifies
filename hashes, parses metadata, resolves dependencies and priorities, mounts
components read-only, creates declared storage and constructs the root OverlayFS.
The runtime `componentctl` can stage a replacement into a new slot and select a
previous slot for rollback.
